# 后台日志、认证与系统设置实施规划

## 目标

补齐管理后台的三项基础能力：真实登录认证、可查询的操作日志，以及可维护的系统配置。实现顺序应先建立认证和权限边界，再记录有责任主体的日志，最后开放受控的系统设置。

## 一、登录认证与权限控制

### 后端

- 新增认证领域接口：登录、刷新令牌、退出登录、获取当前用户。
- 使用 JWT 区分短期 access token 和可撤销、可轮换的 refresh token。
- 沿用并逐步升级现有密码哈希逻辑；登录时验证账号、密码和用户状态。
- 已停用、锁定、软删除的账号不能登录。
- 为现有管理接口增加统一认证依赖；根据用户角色和权限编码返回 `401` 或 `403`。
- 系统管理员仍保留不可由普通管理操作修改的规则。

### 前端

- 登录页改为调用真实后端接口，不再使用静态模拟状态。
- 令牌统一保存、自动随请求携带；遇到失效时尝试刷新，失败后回到登录页。
- 增加路由守卫，未登录用户不能进入管理端；无权限时显示明确提示。
- 当前账号信息从后端读取，用于头像、退出登录和操作日志归属。

### 验收

- 未携带令牌访问管理 API 返回 `401`。
- 已登录但无对应权限访问管理 API 返回 `403`。
- 管理员可管理当前已有功能；停用用户无法继续登录。

## 二、操作日志

### 数据与接口

- 复用现有 `sys_operation_log` 数据表，补充统一写入服务，不由每个路由手写 SQL。
- 记录操作者、操作类型、资源类型、资源 ID、请求 IP、必要的变更摘要和时间。
- 首批覆盖登录、退出、创建/编辑/启停用户、角色、权限、知识库、标签、文档上传、发布和删除。
- 提供分页查询接口，支持按操作人、资源类型、操作类型和时间范围筛选。
- 日志只记录必要摘要，绝不记录密码、JWT、API Key 或文档原文等敏感数据。

### 前端

- 新增“操作日志”模块，接入真实日志查询接口。
- 支持条件筛选、分页、查看结构化变更摘要。
- 默认按最新时间排序，加载或查询失败时给出重试提示。

### 验收

- 每次关键后台操作都能在日志中定位操作者、时间、对象和结果。
- 日志查询不暴露密码或密钥等敏感信息。

## 三、系统设置与 API Key

### 数据与安全

- 新增 `sys_setting` 表，字段包括设置键、显示名称、分类、加密后的值、是否敏感、说明、更新时间和更新人。
- 仅系统管理员可读取或修改系统设置；普通管理员只能看到无敏感配置。
- API Key、第三方服务密码等敏感值必须加密保存，接口和前端只返回脱敏值，例如 `sk-****8K9p`。
- 密钥加密主密钥仅从后端环境变量读取，绝不保存到 MySQL 或提交到 Git。
- 更新敏感配置时必须明确输入完整新值；空值表示保持原值，不能用脱敏值回写。

### 首批配置项

- 模型服务：聊天模型 API Key、Base URL、模型名称。
- Embedding 服务：API Key、Base URL、模型名称和向量维度。
- Milvus：连接地址、数据库或集合名称。
- 文档处理：单文件大小限制、Chunk 大小、Chunk 重叠长度。
- 运行信息：站点名称和默认知识库。

数据库连接、JWT 密钥和设置加密主密钥仍只允许通过环境变量配置，不在后台界面修改，避免将应用基础安全边界暴露到网页中。

### 前端

- 新增系统设置模块，按“模型服务、向量检索、文档处理、站点信息”分组。
- 敏感字段使用密码输入框和脱敏展示，提供“更新”而非“查看明文”的交互。
- 保存前校验必填项、URL 格式、数字范围；保存后提供明确成功或失败反馈。
- 修改 API Key 前显示风险提示，并将操作写入日志。

### 验收

- 系统管理员可安全修改允许在线维护的第三方服务配置。
- 非管理员无法读取、修改或通过接口获取敏感配置明文。
- 修改后的配置能够被后续导入和问答流程读取。

## 推荐实施顺序

1. 完成登录、JWT、当前用户和管理 API 权限依赖。
2. 将管理端登录页、请求拦截和路由守卫接入认证接口。
3. 抽取操作日志服务，并接入关键管理操作和日志查询页面。
4. 创建系统设置表、加密服务和仅管理员可用的设置接口。
5. 实现系统设置页面并接入敏感值脱敏、更新、校验与日志记录。

完成以上内容后，再进入文档导入任务和向量检索的实现。
