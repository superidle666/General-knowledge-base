## 1. 规范总则

### 1.1 核心原则

- **注释只解释语义与业务**：代码本身实现不用注释，只注释「为什么这么写、业务约束、特殊兼容、坑点、边界条件」
- **自解释代码优先**：优先通过变量名、函数名、拆分逻辑提升可读性，杜绝冗余废话注释
- **统一语言**：业务描述使用中文，技术关键字、参数名保留英文，禁止中英文混乱混用
- **禁止无效注释**：严禁大段注释废弃代码、删除线残留代码、密码/内网地址等敏感注释

### 1.2 通用标记约定（全端统一）

- `TODO`：待开发、待优化、待补充逻辑
- `FIXME`：已知BUG，需修复的逻辑
- `NOTE`：重要业务规则、特殊约束、开发注意事项
- `HACK`：临时兼容方案、应急代码，后续需重构
- `DEPRECATED`：废弃方法/接口，标注替代方案与下线时间

### 1.3 注释层级要求

所有项目统一遵循：文件头注释 > 模块/组件/类注释 > 核心方法/函数注释 > 特殊逻辑单行注释

## 2. 前端 Vue3 注释规范（JS/TS/Vue SFC）

适用场景：Vue3 组合式API、Setup语法糖、TS项目、页面组件、公共工具函数、样式

### 2.1 Vue SFC 组件文件头注释

所有页面组件、公共业务组件必须添加文件头，通用基础组件可简化

### 2.2 Template 模板注释

- 仅对**代码区块、复杂业务模块**注释，禁止单行普通标签注释
- 注释独占一行，位于模块上方，不贴标签同行

```vue
<template>
  <div class="order-page">
    <!-- 订单筛选条件区域：时间、状态、关键词筛选 -->

    <div class="order-list">
      <OrderItem v-for="item in orderList" :key="item.id" :info="item" />
    </div>
  </div>
</template>
```

### 2.4 变量/常量注释

全局常量、业务状态枚举、特殊配置必须注释；普通临时变量无需注释


### 2.5 Style 样式注释

- 仅对独立模块样式、特殊兼容样式、全局样式添加注释
- 普通样式、简单布局无需注释

```scss
/* 订单卡片通用样式：适配移动端/桌面端自适应 */
.order-card {
  width: 100%;
  border-radius: 8px;
}

/* 兼容低版本浏览器：修复flex布局错位问题 */
.flex-wrap {
  display: -webkit-box;
  display: flex;
}
```

### 2.6 前端禁止写法

```typescript
// ❌ 冗余废话注释

// ❌ 无意义单行注释
// 循环遍历数组
```

### 3.2 Model 模型注释

模型类、所有字段必须添加注释，明确业务含义、取值范围

```python
from django.db import models

class OrderInfo(models.Model):
    """订单信息模型
    
    存储用户消费订单数据，关联用户、商品、支付记录
    状态变更由订单业务逻辑统一控制，禁止手动修改数据库
    """
    ORDER_STATUS_CHOICE = (
        (0, "待支付"),
        (1, "已支付"),
        (2, "已核销"),
        (3, "已取消"),
    )
    order_no = models.CharField(max_length=64, verbose_name="订单唯一单号")
    user_id = models.BigIntegerField(verbose_name="关联用户ID")
    status = models.SmallIntegerField(choices=ORDER_STATUS_CHOICE, default=0, verbose_name="订单状态")
    create_time = models.DateTimeField(auto_now_add=True, verbose_name="订单创建时间")

    class Meta:
        verbose_name = "订单信息表"
        verbose_name_plural = verbose_name
        db_table = "order_info"
```

## 5. 全端统一禁止规则

1. 禁止注释代码实现逻辑，只能注释业务规则、特殊场景、遗留问题
2. 禁止保留大段注释废弃代码，无用代码直接删除
3. 禁止在注释中写入密钥、密码、服务器地址、接口秘钥等敏感信息
4. 禁止中英文混杂无意义注释，禁止口语化、模糊化注释
5. 禁止无注释的核心业务函数、接口、状态枚举
