# 文档管理模块实施规划

## 一、当前基础

项目目前已经具备：

- MySQL 文档表 `kb_document`。
- 文档分段表 `kb_document_chunk`。
- 文档标签表。
- 文档状态：`uploaded`、`processing`、`published`、`failed`、`archived`。
- 文档列表、创建、更新、归档接口。
- 文档分段查询接口。
- 管理端文档列表页面。

当前示例数据中的 `vector_id` 主要用于演示。真实的文件解析、Embedding 生成、向量数据库写入、删除同步和异步任务流程还需要补齐。

## 二、第一阶段：文档管理基础功能

### 1. 文档列表

展示文档名称、所属知识库、文件类型、文件大小、更新时间、文档状态、Chunk 数量和操作按钮。

支持按知识库、状态、文件类型筛选，并支持按名称搜索。

| 状态 | 说明 |
| --- | --- |
| `uploaded` | 已上传，等待处理 |
| `processing` | 正在解析或向量化 |
| `published` | 已发布，用户端可以检索 |
| `failed` | 处理失败 |
| `archived` | 已归档，不参与检索 |

### 2. 上传文档

管理端上传表单包含选择文件、选择知识库、输入文档标题和添加标签。后端保存原始文件名、文件大小、MIME 类型、文件哈希、存储路径、所属知识库、上传用户和初始状态。

第一阶段使用本地文件存储，后续可替换为 MinIO 或 OSS。

```text
storage/
└── libraries/
    └── industrial-equipment/
        └── 2026/
            └── 08/
                └── 文件名.pdf
```

### 3. 文档详情

展示文档基本信息、所属知识库、当前版本、文件大小、上传时间、更新时间、处理状态、解析错误、Chunk 数量、向量索引状态和标签列表。

### 4. Chunk 预览

展示 Chunk 序号、内容、页码、Token 数量、向量 ID 和创建时间，并支持分页和关键词搜索。

## 三、第二阶段：文档处理流程

### 1. 文件解析

| 文件类型 | 推荐技术 |
| --- | --- |
| PDF | PyMuPDF |
| DOCX | python-docx |
| TXT | Python 标准库 |
| Markdown | Markdown 解析器 |
| Excel | openpyxl |

解析结果包括正文、页码、标题层级、表格内容和解析错误。

### 2. 文本清洗和切分

- 移除多余空格和无意义换行。
- 清理页眉页脚和乱码。
- 保留标题层级和页码。
- 默认 Chunk 大小为 500 至 800 Tokens。
- 默认 Chunk 重叠为 50 至 100 Tokens。

每个 Chunk 保存：

```text
document_id
chunk_index
content
page_number
section_title
token_count
vector_id
```

### 3. Embedding 和向量写入

```text
Chunk 文本
  ↓
Embedding 模型
  ↓
生成向量
  ↓
写入向量数据库
  ↓
保存 vector_id 到 MySQL
```

向量元数据至少包括 `document_id`、`chunk_id`、`library_id`、`status`、`version` 和 `page_number`。

向量数据库初期推荐 Qdrant；数据规模增大后可使用 Milvus。MySQL 保存业务数据和可追踪关系，向量数据库保存相似度检索所需的向量。

### 4. 异步处理和状态流转

```text
上传文件 → 创建文档记录 → processing
                         ↓
                 解析、清洗、切分
                         ↓
                 Embedding 和向量写入
                         ↓
                   published / failed
```

初期可以使用 FastAPI `BackgroundTasks`，后续使用 Celery + Redis。Redis 用于任务队列、任务状态和失败重试，不保存文档正文。

### 5. 索引校验

发布前检查文件是否存在、是否解析成功、是否生成 Chunk、每个 Chunk 是否存在向量 ID，以及 MySQL Chunk 数量和向量数据库数量是否一致。

## 四、第三阶段：发布、归档和版本管理

### 1. 发布和下架

- 发布：允许用户端检索。
- 下架：停止检索但保留数据。
- 归档：MySQL 软删除，同时删除或禁用对应向量。

用户端检索必须过滤 `document.status = 'published'`。

### 2. 重新索引

1. 删除旧 Chunk。
2. 删除旧向量。
3. 文档状态改为 `processing`。
4. 重新解析和切分。
5. 重新生成向量。
6. 写入新 Chunk 和向量。
7. 完成后恢复为 `published`。

### 3. 文档版本

同一文档重新上传时生成新版本。新版本处理完成并发布后，旧版本自动下架但保留历史记录。

## 五、后端接口规划

### 文档接口

```text
GET    /api/v1/documents
POST   /api/v1/documents/upload
GET    /api/v1/documents/{document_id}
PATCH  /api/v1/documents/{document_id}
DELETE /api/v1/documents/{document_id}
POST   /api/v1/documents/{document_id}/publish
POST   /api/v1/documents/{document_id}/unpublish
POST   /api/v1/documents/{document_id}/reindex
```

### Chunk 接口

```text
GET    /api/v1/documents/{document_id}/chunks
GET    /api/v1/documents/{document_id}/chunks/{chunk_id}
```

### 任务接口

```text
GET    /api/v1/documents/{document_id}/task
POST   /api/v1/documents/{document_id}/retry
```

### 标签接口

```text
GET    /api/v1/tags
POST   /api/v1/tags
POST   /api/v1/documents/{document_id}/tags
DELETE /api/v1/documents/{document_id}/tags/{tag_id}
```

## 六、前端页面规划

```text
pages/admin/documents/
├── index.vue                 # 文档列表
├── DocumentUploadDialog.vue  # 上传文档
├── DocumentDetail.vue        # 文档详情
├── DocumentChunks.vue        # Chunk 预览
├── DocumentFilters.vue       # 筛选条件
└── documentTypes.ts          # 类型定义
```

文档列表操作包括查看详情、发布/下架、重新索引和归档。详情页操作包括编辑信息、查看 Chunk、查看处理错误、重新处理、查看版本和查看索引状态。

## 七、推荐实施顺序

1. 文档详情接口。
2. Chunk 查询接口。
3. 管理端文档详情页。
4. 文件上传接口。
5. 本地文件保存。
6. PDF、DOCX 文本解析。
7. Chunk 切分。
8. 后台处理任务。
9. Embedding 接口。
10. 向量数据库写入。
11. 发布前索引校验。
12. 重新索引和失败重试。
13. 文档版本管理。
14. 用户端真实检索。

建议先实现第一阶段：文档列表增强、文件上传、文档详情和 Chunk 预览，形成稳定的管理闭环后再接入耗时较长的解析和向量化任务。
